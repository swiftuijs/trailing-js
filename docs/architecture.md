# Architecture

`packages/twill/src/parser.js` extends Acorn's expression parser and delegates JS, TS, JSX, function scopes, and control flow to its normal parsers. Tokenized lookahead recognizes the optional `parameters in` header and contextual guard statements. Guard failure paths undergo conservative exit validation. Acorn's arrow-function scope implementation validates parameter bindings and permits return/await. TS extension backtracking is accounted for by retaining only closures/calls/guards reachable in the final AST. Parser subclasses are cached per grammar; parser state and closure metadata remain per invocation. Parameter locations use one lazy line index rather than rescanning the entire source for each node.

`packages/twill/src/compiler.ts` edits original offsets with MagicString. It preserves comments, whitespace, ordinary syntax, and original parameter tokens. Guards preserve bindings and expressions and lower to native if statements. Moving a closing parenthesis around the closure avoids regeneration of the rest of the file. Component closures in `.twillx` lower to native JSX and use hygienic collectors and visit statement scopes without descending into nested functions or classes. Maps contain the original source text and token-level positions. Ordinary callbacks avoid identifier-hygiene traversal; component children and defer scan identifiers to allocate collision-free locals. Mapping decoders live in a WeakMap keyed by the transformation result.

`packages/twill/src/defer.ts` finds lexical blocks and lowers reached registrations into lazy local stacks with finally drains. Cleanup parsing uses a real arrow scope so illegal outer jumps and synchronous await are rejected. Mixed async/sync registrations await only explicit async cleanup. Drains retain the last error while running every callback. Function-body declarations are normalized into hoisted variable bindings and function initializers inside the try's lexical environment, retaining directives, TDZ captures, JS parameter aliases and attached JSDoc. Original tokens are moved rather than regenerated, preserving diagnostic positions. Overload declarations in these function bodies are rejected explicitly.

Class heritage parsing suppresses trailing-closure recognition at the class body's brace. The pinned acorn-typescript 1.4.13 parser has an inverted derived-class override check; a narrow parser hook bypasses that false positive for derived TS elements, while TypeScript still validates override semantics. Compatibility tests cover derived classes and cleanup use of super.

`packages/twill/src/transpile.ts` bypasses type transpilation for plain JS, erases TS types and lowers JSX with TypeScript, then composes its map with the syntax map. Native TS/TSX/JSX uses a separate emitter entry without Twill parsing and maps to its actual source filename. Vite/esbuild retain native host emission by default; Rollup/webpack/rspack can use that emitter. `packages/twill/src/files.ts` resolves local native sources before Twill and handles indexes, dependency exclusions and query suffixes. The esbuild adapter forwards native dependencies from its custom namespace to the host resolver. Compiler users can keep TypeScript intact through `transform()`. The Node loader emits local native ESM TS as well as Twill; JS/CJS and npm dependencies remain with Node.

`packages/twill/src/project.ts` presents virtual standard filenames to a TypeScript language service: `.twill` becomes a virtual TS filename and `.twillx` becomes a virtual TSX filename. Discovery follows tsconfig includes/excludes; module resolution delegates to TypeScript first and then checks local Twill files. Dialect snapshots are lowered before TypeScript sees them; native JS/JSX snapshots retain their ScriptKind and JSDoc behavior. Diagnostics and editor spans map between original and generated offsets. Overlay changes advance the project version and only the changed script version; TypeScript tracks dependencies. Unchanged overlays retain transforms and semantic snapshots. Line indexes and mapping decoders are cached for editor requests. Disk refresh invalidates only the affected file; create/delete refreshes root discovery while retaining unrelated transforms and unsaved overlays. Configuration changes rebuild only affected projects. Explicit full invalidation remains available. The CLI uses strict parsing; the editor can repair a small number of common incomplete inputs for assistance while still reporting strict syntax errors.

Component closures lower directly to native JSX in `.twillx`; no Twill React/Vue adapter or component wrapper is supplied. React gets direct single-expression children, collectors for general control flow, or lazy function children for parameterized render-prop closures. Vue gets lazy default and named slot objects. Runtime selection follows normal JSX settings and file pragmas, with direct Vue imports as a fallback. TypeScript's emitter uses the selected standard JSX runtime; the compiler itself does not load either framework.

The VS Code extension bundles TypeScript, standard-library declarations and the compiler into its extension host, uses language providers with lazy completion-detail resolution, and reads the same JSON configuration as builds. `packages/twill/src/typescript-plugin.ts` bridges native TS/JS documents to a cached virtual project and maps cross-file definitions and related diagnostics. The shared `packages/twill/src/editor.ts` layer handles partial React prop keys, auto-imports, rename, import organization and safe code fixes. Edits require an exact source-token mapping; synthetic helper and closing-tag references are omitted. React shorthand prop renames preserve the other side of the key/value binding. Native host script versions retain unchanged snapshots without restatting tracked files; untracked dependencies use filesystem versions. Unsaved dialect overlays arrive through the native TS extension configuration API. Its CommonJS bundle is loaded by TS server via the npm package main; compiler ESM consumers retain normal package exports. The bridge uses native host library paths while standalone providers use bundled declarations. Real TS-server protocol probes test the independently installed npm entry and extracted VSIX, including unopened dialect dependencies outside include globs. TextMate grammars delegate normal language regions to VS Code's bundled TS/JS grammars. No user application code or executable configuration is run by the editor.

Tests exercise behavior by executing lowered closures, checking actual diagnostics and maps, invoking bundlers, rendering independent components, and installing the packed package into a clean consumer. Package verification also builds and server-renders the real `@swiftuijs/ui` example and the Vue example.

## Workspace builds

The private root is a pnpm workspace. `packages/twill` is the published compiler/toolchain; `editors/vscode` is the extension; its private `twill-typescript-plugin` workspace supplies the automatic VS Code TS-server bridge. Workspace dependencies define build order and keep imports on public package APIs. Shared configuration and validation remain at the root.

Vite 8 library mode (Rolldown) builds the compiler's ESM entries and CJS TS-server entry, standalone editor bundles, and extension-host test bundle. `vite-plugin-dts` emits declarations for the tool's own TypeScript API. It does not implement declaration emission for user Twill libraries. Runtime dependencies remain external in the public ESM compiler; the editor embeds its dependencies and standard-library declarations. VSIX staging copies only required production files, avoiding reliance on pnpm hoisting or workspace symlinks.

Tests install the public tarball through an independent npm consumer. Real VS Code extension-host tests load the extracted VSIX and invoke editor providers with source edits and unsaved buffers, then launch the Node debugger and inspect original-line stops. The CI matrix includes the minimum supported VS Code version and stable.
